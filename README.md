# Spiral

Comunication

No se entrena un agente; se entrena un sistema.

Principios:
- La IA refleja al usuario, no lo reemplaza.
- El centro sigue siendo la intención humana.
- GitHub guarda la memoria, el contexto y el recorrido.
- La espiral organiza el movimiento, la relación y la adaptación.
- El sistema adopta su forma según su funcionamiento, no por fuerza de etiqueta.

Este repositorio es un espacio para explorar la relación entre:
- usuario
- IA
- contexto
- memoria
- comunicación
- sistemas vivos y adaptativos

No es un repositorio técnico aislado. Es un repositorio de observación, estructura y evolución.

### Tema 2
- Fecha: 29 de octubre
- Lugar en la espiral: **centro** — la intención humana. GitHub aquí es **periferia**: memoria, no centro.
- Encuadre: el entrenamiento técnico (GitHub, Python, IA) no es el fin; es el medio para sostener un objetivo humano complejo.

Idea central: las skills no son el producto; son capas del sistema que traducen intención en forma operable.

Resumen:
- **Centro:** intención humana y criterio. Es donde se decide qué vale y qué no.
- **Periferia:** GitHub como memoria del recorrido. Guarda, no decide.
- **Skills / habilidades:** no son etiquetas, son la relación entre formatos y función:
  - `markdown` → legibilidad y estructura para humano.
  - `yaml` → configuración y criterio declarativo.
  - `json` → intercambio y estructura para máquina.
  - `python` → ejecución y transformación.
- Toda skill previa debe probarse contra el centro: ¿reduce riesgo, aclara señal o solo añade ruido?

Foco de esta vuelta:
- Rediseñar, depurar y pasar a la **siguiente vuelta de la espiral** las skills / complementos previos de OpenAI (ChatGPT).
- Núcleo de trabajo: **Tratamiento especial y Protocolo de revisión de documentos legales, no limitado a los mismos.**

Siguiente paso:
- Inventariar skills actuales de ChatGPT (markdown/yaml/json/python).
- Depurar: qué se conserva, qué se fusiona, qué se elimina.
- Formalizar el Protocolo de revisión como skill central transferible.
- Guardar en GitHub solo el rastro mínimo necesario (memoria periférica).

### Tema 3 — Acotación
- Fecha: 29 de octubre (noche)
- Lugar en la espiral: centro — redefinición del objetivo.
- Corrección: olvidar por ahora LGDNNA / protocolo infancia como mezcla. El precedente se construye después; ahora el foco técnico es otro.

Idea central: analizar de manera independiente el **Acuerdo General 12/2020** — sin mezclarlo con el fondo de menores. Es el riel, no la carga.

Objetivo 1 — Skill que quede:
- Que quede una skill útil para analizar los **diversos acuerdos** (son varios, cada uno con su lógica). 
- Herramienta especializada, no genérica, calibrada a este caso específico (NEUN, expediente electrónico, Libros de Gobierno).

Objetivo 2 — Partir del resultado:
- Partimos del resultado ya documentado (`neunarena.md`: NEUN 41504452 sobrepuesto, 000000 como control actual, outlier 38654211).
- Intrínsecamente en segundo plano, el sistema desarrolla automáticamente el flujo del asunto (reconstrucción inversa: del resultado → a la cadena rota).

Siguiente paso:
- Diseñar la skill `analizador-acuerdos` solo sobre el 12/2020 como base independiente.
- Validar que esa misma estructura sirva para los demás acuerdos sin reescribirla.
- Dejar que el flujo se genere en segundo plano desde el resultado ya aterrizado.
